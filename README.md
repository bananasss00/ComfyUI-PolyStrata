# ComfyUI-PolyStrata

Ноды ComfyUI для локального сервера [PolyStrata](https://github.com/VecSzn/PolyStrata):
чат с текстом, картинками и видео (кадрами) без стриминга + управление памятью GPU.
Сервер вы запускаете сами; ноды только шлют запросы по HTTP - никаких путей к GGUF,
ngl, ctx_size и прочих llama.cpp-параметров.

**Версия 0.9.0** (новое: ВЫБОР МОДЕЛИ в главной ноде - дропдаун установленных моделей сервера
(`GET /api/models`, реестр `strata-*.json`; список перечитывается при обновлении страницы браузера **F5**
или горячей клавишей **R** в ComfyUI, кеш 15 c); выбранная модель, если она не текущая,
**переключает сервер до генерации** (`POST /api/models/load`: текущий движок останавливается,
новая грузится по своему конфигу `strata-<модель>.json`; сентинел `как на сервере` = не влиять,
как в v0.8.0). Из v0.8.0 - КОМПАКТНЫЙ интерфейс - убраны виджеты `api_key`/`extra_mib`
(доступ localhost; резерв - один `reserve_mib`), `top_k` переехал в чат после `top_p`, лимиты кадров
(`max_frame_side`/`max_images`/`max_video_frames`/`video_fps`) - в опциональную субноду
**PolyStrata Media** (вход `media`; без неё - дефолты 1024/16/8/0). Старые воркфлоу грузятся:
лишние значения игнорируются, новым входам подставляются дефолты; заданный в старом Sampling
`top_k` пере-задайте в чате. Из v0.7.5 - обработка листов на входах БЕЗ хардкода имён
виджетов: весь kwargs прогоняется через один универсальный нормализатор.
Из v0.7.4 - тоггл `clear_comfy_vram` - ПЕРЕД генерацией выгрузить модели САМОГО ComfyUI
и почистить torch-кэш, как кнопка 'Free model and node cache'; в одном запуске воркфлоу очистка
делается ОДИН РАЗ - лист картинок на входе, цикл list-пака, перебор сидов или несколько нод Chat
не дёргают память повторно; листы на ЛЮБЫХ входах обрабатываются безопасно: скалярные виджеты
берут первый элемент, списки батчей картинок разворачиваются в пины одним запросом. Из v0.7.3 -
авто-выгрузка модели, когда главная нода забайпашена или открыт другой воркфлоу; из v0.7.1 -
Cancel ComfyUI рвёт соединение ПО-НАСТОЯЩЕМУ (interruptible-запрос на http.client, сокет
закрывается - FIN - и watch-поток PolyStrata отменяет генерацию движка); из v0.7.0 - метки
времени видео `<X.X seconds>` + виджет `video_fps`, блок `[Video N]`; из v0.6.0 - лимиты кадров
НА КАЖДЫЙ пин, seed/max_frame_side в главной ноде, подгонка кадров под контекст движка,
рабочий выключатель размышлений, без дубликатов сэмплинга).

## Состав

| Нода | Что делает |
| --- | --- |
| **PolyStrata Chat** | **Schema V3** (`comfy_api.latest`): генерация промпт + **дропдаун модели сервера** (`model`: `как на сервере` - не влиять; выбранная модель **переключает сервер** до генерации - см. «Смена модели» ниже; список установленных моделей обновляется **F5** / **R**) + **пресеты системных промптов** (`system_prompt_preset` - .txt из `ComfyUI/models/LLM/prompts`, тот же путь, что в llama.cpp-нодах; выбранный пресет перекрывает ручной `system_prompt_text`; список обновляется при перезагрузке страницы ComfyUI) + картинки (`img_0`, `img_1`, ... - autogrow) + видео (`vid_0`, `vid_1`, ... - ОТДЕЛЬНАЯ autogrow-группа, каждый пин = отдельное видео кадрами, `video_fps` - метки времени `<X.X seconds>` между ними). Выходы: `text` + `thoughts` (размышления отдельно). `reasoning`/`temperature`/`top_p`/`top_k`/`seed` - только здесь. Лимиты кадров - в опциональной субноде Media (вход `media`), действуют НА КАЖДЫЙ пин своего типа; перед отправкой кадры подгоняются под контекст движка (двигок запросы не обрезает). **Cancel (interrupt) ComfyUI прерывает генерацию** - соединение закрывается, сервер отменяет запрос. Виджет `reserve_mib` - резерв VRAM для ComfyUI; тоггл `clear_comfy_vram` - выгрузить модели ComfyUI перед генерацией (один раз на запуск воркфлоу, см. «Очистка памяти ComfyUI» ниже). Листы на входах (list-паки/циклы) безопасны: скаляры - первый элемент, списки батчей - один запрос. Без стриминга. Сама по себе - **одиночный запрос**. |
| **PolyStrata Sampling** | Доп. сэмплинг **без дубликатов** (temperature/top_p/top_k/reasoning/seed - в чате): `min_p`, `repeat_penalty`, `repeat_last_n`, `presence/frequency_penalty`, `stop` (до 4 строк), **`logit_bias`** (запрет токенов, как banned_tokens в llama-нодах) и **`extra_sampling`** (JSON-сквозняк для будущих полей движка). Подключается ко входу `sampling`; заданное перекрывает чат; `-1`/пусто = «не задано». |
| **PolyStrata Media** | Опциональная субнода лимитов кадров для чата: `max_frame_side` (ужатие длинной стороны, 0 = без ужатия), `max_images` (лимит НА КАЖДЫЙ пин картинок, 0 = все кадры), `max_video_frames` (лимит НА КАЖДЫЙ видео-пин, 0 = все кадры), `video_fps` (метки времени `<X.X seconds>` между кадрами видео). Подключается ко входу `media`; без неё у Chat - значения по умолчанию (1024/16/8/0). |
| **PolyStrata Memory** | История разговора (multi-turn): копит пары вопрос-ответ между запусками. Подключается ко входу `memory`; без неё чат одиночный. В историю пишется только текст. Тоже принимает пресет системного промпта (`system_prompt_preset` из `models/LLM/prompts`); перекрывает системный промпт чата. |
| **PolyStrata Unload** | **Полная** выгрузка модели (`POST /v1/unload`): вся VRAM и RAM свободны, сервер жив; снимает серверный резерв и **возвращает ComfyUI исходное `EXTRA_RESERVED_VRAM`**. Сквозная: `any_input` → `any_output`. Плюс **авто-выгрузка** без ноды: главная нода забайпашена / открыт другой воркфлоу - модель выгружается сама (как в llama.cpp-нодах; см. «Авто-выгрузка» ниже). |

На ComfyUI **без** `comfy_api` нода Chat автоматически собирается в V1-варианте
(фиксированные входы `images`/`videos`) - поведение то же.

## Требования

1. **Сервер PolyStrata запускаете вы** (run-`<модель>`.bat / START-HERE.bat); в нодах - только его адрес (`IP:порт`, по умолчанию порт 8080).
2. **Движок strata-poly 0.1.45-poly.6 или новее** - обновляется `UPDATE.bat`. Elastic VRAM (сегментированный кэш экспертов) в нём **встроен**.
3. **НЕ добавляйте `"vram_elastic": true` в конфиг strata-poly-модели** (`strata-<модель>.json`) - это причина ошибки `strata-poly: unknown option --vram-elastic`. Если ключ попал в конфиг - удалите его и запустите модель заново.
4. Для картинок/видео модель должна быть запущена с vision (блок `"vision"` + mmproj, «Images?» в setup).

## Установка

- Скопируйте папку `ComfyUI-PolyStrata` в `ComfyUI/custom_nodes/` (или распакуйте `ComfyUI-PolyStrata.zip` туда же) и перезапустите ComfyUI. Зависимость - `requests` (уже есть в окружении ComfyUI). Тесты пакета: `python tests/test_nodepack.py` (нужны numpy/PIL; mock-сервер включён).

## Картинки и видео: autogrow-пины (schema V3)

Как в llama.cpp-нодах (LlamaCPP-Subprocess): у ноды Chat две ОТДЕЛЬНЫЕ динамические
группы входов. Подключите последний свободный пин - появится следующий (до 50):

- **`img_0`, `img_1`, ...** (IMAGE) - картинки, можно батч `[N,H,W,C]`. Кадры всех пинов
  раскрываются по одному со сквозными метками `[Image 1]`, `[Image 2]`, ...;
  `max_images` (субнода Media) - лимит кадров **НА КАЖДЫЙ пин** картинок (внутри пина
  выборка равномерная, `np.linspace`; `0` = все кадры пина, потолок 64/пин);
- **`vid_0`, `vid_1`, ...** (IMAGE, батч последовательных кадров - выход «Load Video» /
  Video Helper Suite) - видео. **Каждый vid-пин = отдельное видео**: блок `[Video 1]` и
  кадры по порядку. `max_video_frames` - лимит кадров **НА КАЖДЫЙ видео-пин**: два видео
  и 8 = по 8 кадров на КАЖДОЕ (`0` = все кадры пина, потолок 128/пин); `video_fps`
  (там же) - FPS исходника для меток времени (см. ниже);
- кадры уходят как `image_url` (base64 JPEG, длинная сторона ≤ `max_frame_side`, по
  умолчанию 1024); аудио не передаётся;
- **метки времени**: при `video_fps` > 0 перед КАЖДЫМ кадром видео вставляется
  `<X.X seconds>` - время от индексов кадров ИСХОДНОГО батча (выборка `max_video_frames`
  сохраняет исходные индексы), поэтому указывайте fps исходника. Без меток (0) - только
  блок `[Video N]`;
- **прерывание**: кнопка Cancel (interrupt) ComfyUI останавливает ноду в любой момент -
  interruptible-запрос идёт через http.client, при Cancel сокет закрывается ПО-НАСТОЯЩЕМУ
  (FIN), и watch-поток PolyStrata (`_watch_client`: select + MSG_PEEK каждые 0.5 c) видит
  EOF и отменяет генерацию движка («client went away: stop the engine») - в логе ноды
  «ПРЕРВАНО (Cancel ComfyUI)»; ход в память Memory при этом не записывается.

### Видео по кадрам: как это делает Jan и почему модель отвечала «Frame 1: ...»

Как видео доходит до локальной модели в чатах (проверено по коду Jan, janhq/jan): Jan
НЕ нарезает кадры сам - он шлёт видеофайл ЦЕЛИКОМ одной content-частью
`{"type": "input_video", "input_video": {"data": "<base64 mp4>"}}` (алиас - `video_url`),
а llama.cpp-движок (server-common.cpp, обработка `input_video`/`video_url`) декодирует его
через ffmpeg: кадры + метки времени `<X.X seconds>` перед каждой темпоральной группой
(mtmd-helper.cpp: `snprintf(ts_buf, "<%.1f seconds>", ts_s)`). Модель обучена на видео с
такими метками и видит одну непрерывную последовательность.

PolyStrata этот путь НЕ поддерживает (в serve/server.py - 0 упоминаний video: принимаются
только image_url-части и Anthropic-блоки картинок), а ComfyUI отдаёт ноде готовый батч
кадров, а не файл. Поэтому нода воспроизводит разметку движка сама:

- блок `[Video N]` вместо «[Video N - X sequential frames]» - слово «frames» в метке само
  провоцировало модель перечислять кадры («Frame 1: ...», «Frame 5: ...»);
- при `video_fps` > 0 - метки `<X.X seconds>` перед каждым кадром, ровно как llama.cpp.
  Без меток модель с высокой вероятностью отвечает по кадрам.

Важно про связку «Jan → PolyStrata» (OpenAI-compatible API): даже подключив Jan прямо к
PolyStrata, видео до модели НЕ довести - Jan шлёт часть `input_video`, а PolyStrata части
неизвестных типов выбрасывает молча (serve/frontend.py `_check_parts`: «left out of the
prompt», в логе сервера - debug-строка; читаются только image_url/input_image/image).
Никаких текстовых подсказок к видео Jan тоже не добавляет. Так что кадры с метками времени -
не «костыль», а единственный способ передать видео в PolyStrata, и разметка та же, на
которой модель обучена.

Совет: ставьте FPS исходного видео (16-30) и просите «опиши видео как непрерывное
событие» - метки дадут модели таймлайн, формулировка уберёт перечисление.

### Почему кадры «съедают» контекст и что с этим делает нода

У Qwen-VL один vision-токен ≈ 28×28 пикселей: кадр 1280×720 ≈ **1200 токенов**, 8 кадров ≈
9600, а 16 кадров двух видео - вдвое больше. Двигок такие запросы **не обрезает** -
отклоняет целиком (`400 ... exceeds the context window ... requests are never truncated`).
Поэтому нода Chat:

1. узнаёт окно движка из `/v1/status` (`context.native`, запасной путь - `/props`);
2. считает оценку промпта (кадры по формуле 28 px/токен + текст + запас под `max_tokens`);
3. если оценка не влезает - **урезает кадры до отправки** (равномерно по каждому видео/пину)
   и пишет в лог: `КОНТЕКСТ 32768 токенов: кадров 24 -> 12 (...)`.

Итоговые ручки (субнода Media): `max_video_frames`/`max_images` (лимиты на каждый пин),
`video_fps` (метки времени между кадрами видео), `max_frame_side`
(длинная сторона кадра: меньше - дешевле кадр в токенах); плюс `max_turns` ноды Memory.

## Смена модели на работающем сервере

Сервер PolyStrata умеет менять модель **не перезапускаясь** (то самое `[strata] switching
the model: ...` в его консоли). Нода Chat теперь пользуется этим через виджет `model`:

- **`как на сервере`** (по умолчанию) - не влиять: генерация идёт загруженной моделью,
  поле `model` в chat-запрос НЕ пишется (поведение v0.8.0, старые воркфлоу не меняются);
- **выбранная модель** - если она не текущая, нода ДО генерации переключает сервер
  (`POST /api/models/load`), затем шлёт запрос уже новой модели; если текущая - ничего
  не делает (лишний раз сервер не дёргается).

Как это проходит на сервере: идущая генерация **дорабатывает** (сервер ждёт до 120 c,
потом отказ 409); текущий движок останавливается - вся его VRAM/RAM освобождаются;
новая модель грузится по **своему** конфигу - первый старт идёт минуты (эксперты не в
кэше), последующие - секунды. **Cancel (interrupt) переключение НЕ обрывает** - это
состояние сервера, а не запрос: он доводит его до конца, нода лишь перестаёт ждать.
После переключения нода сбрасывает кеш окна контекста (у новой модели оно своё) и,
если бронью VRAM ComfyUI управлял нодпак, обновляет её по факту.

### Откуда список и конфиги загрузки

- **Список в дропдауне** - `GET /api/models`: реестр всех **установленных** моделей
  (корень установки PolyStrata: каждый `strata-<имя>.json` = одна модель). Сервер
  перечитывает реестр **на каждый запрос** - новый `strata-*.json` подхватывается без
  перезапуска сервера. Ноды кешируют список на 15 c и обновляют его при построении
  схемы: **F5** (обновление страницы браузера) и **R** в ComfyUI перезапрашивают
  `/object_info` - дропдаун показывает свежий список.
- Так как при построении схемы значение виджета `server` ещё неизвестно, список
  собирается по серверу по умолчанию (`127.0.0.1:8080`) **плюс** всем серверам, которыми
  нодпак уже пользовался в этой сессии (после первого запуска воркфлоу ваш адрес
  попадает в список автоматически). Несколько серверов = объединение списков: модель
  чужого сервера даст понятную 404-ошибку, сервер перечислит доступные имена.
- **Конфиг загрузки** - `strata-<модель>.json` (его пишeт setup при установке модели):
  `exe` - какой движок запускать (strata-poly / strata), `args` - аргументы движка
  (`--model <путь к GGUF>`, `--max-context`, `--draft-model`, mmproj-видеонкодер в
  блоке `vision` и т.д.), `tokenizer` - папка токенизатора, `model_name`/`aliases`/
  `display_name` - имена. Сервер берёт из него ВСЁ: обе модели одновременно в память
  не грузятся - при переключении старая выгружается полностью, новая стартует по своим
  аргументам и своим сэмплерам по умолчанию. Правите `args` в конфиге - изменения
  применятся при следующей загрузке этой модели (переключитесь туда или перезапустите
  сервер).
- Имя в запросе `POST /api/models/load {"model": ...}` - id модели, имя её конфига или
  уникальное подстрочное вхождение; серверная утилита `polystrata models` показывает
  тот же список с VRAM/квантованием.

| Ошибка переключения | Что значит |
| --- | --- |
| 404 `no model named '...'` (в теле - список имён) | Такой модели нет на этом сервере - обновите дропдаун (F5/R). |
| 409 `model_busy` | Генерация шла дольше 120 c - дождитесь и повторите. |
| 422 | Конфиг модели неисправен (проверьте `strata-<модель>.json`: exe/args/tokenizer). |
| 503 | Новая модель не стартовала; сервер вернул прежнюю (см. лог сервера). |

На **старом** сервере без `/api/models` дропдаун покажет только текущую модель (из
`/v1/status`), а попытка переключиться уйдёт в запасной путь `POST /v1/load` - он
работает лишь при включённом на сервере `"switch_on_request": true`; иначе будет
404 `model not found` (обновите PolyStrata).

## Память: резерв VRAM для ComfyUI + Unload

| Способ | Где | Что освобождается | Модель после |
| --- | --- | --- | --- |
| `reserve_mib` | нода Chat | кэш экспертов, пока свободной VRAM не станет `reserve_mib` MiB | работает на пониженном потреблении: недостающие эксперты считаются на CPU (декод медленнее), зато тёплая и кэш отрастает сам |
| `Unload` | нода Unload | **вся** VRAM + RAM модели | спит; следующий чат-запрос разбудит её сам (тёплый старт) |

Как это работает:

- `reserve_mib = 0` - нода **никак не влияет** ни на PolyStrata, ни на бронь ComfyUI
  (запрос `/v1/vram` не отправляется);
- `reserve_mib > 0` - перед генерацией нода читает `/v1/status`, затем
  `/v1/vram {"reserve_mib": reserve_mib}` и сверяет ответ: частичный успех у
  PolyStrata - это HTTP 200, поэтому нода сравнивает `vram_free_mib` с запросом и помечает
  «ЧАСТИЧНОЕ ОСВОБОЖДЕНИЕ» в логе;
- **бронь для ComfyUI** (метод `update_global_vram_reservation` из llama.cpp-нод):
  в `comfy.model_management.EXTRA_RESERVED_VRAM` (и в headroom DynamicVRAM/comfy-aimdo,
  если он активен) записывается **ФАКТИЧЕСКОЕ** потребление PolyStrata - `total GPU −
  фактически свободно` по ответу сервера, а не запрошенная цель (вы можете просить 16000,
  но реально освободилось меньше). Поэтому ComfyUI при загрузке
  своих моделей не выходит за пределы допустимого окна и не ловит OOM;
- **при выгрузке значения возвращаются**: нода Unload восстанавливает исходное
  `EXTRA_RESERVED_VRAM`; то же происходит, если при reserve-запросе модель оказалась спящей;
- сервер **запоминает** резерв и держит его (даже после unload - применит при следующей
  загрузке); вернуть полный кэш - нода Unload (она сбрасывает резерв к стартовому) или
  перезапуск сервера;
- резерв не применился (409/400/нет связи) - генерация всё равно проходит, нода пишет
  «РЕЗЕРВ НЕ ПРИМЕНЁН» в лог.

### Авто-выгрузка: главная нода забайпашена / открыт другой воркфлоу

Тот же механизм, что в llama.cpp-нодах (`hooked_execute` + `unload_all_models`),
только вместо kill процесса - `POST /v1/unload`:

- нода Chat при генерации помечает свой сервер как используемый (сессия ComfyUI);
- при **каждом запуске воркфлоу** ComfyUI (хук на `PromptExecutor.execute`) нодпак
  проверяет: сервер есть в наблюдении, но среди ЖИВЫХ нод Chat/Unload его нет
  (главная нода **забайпашена** - новый фронтенд шлёт `BypassedNode__<класс>`, старый
  `mode: 4`; открыт **другой воркфлоу**; ноды удалены) - серверу уходит `POST /v1/unload`
  (в фоновом потоке, очередь не ждёт; до 30 c ожидания активной генерации - она
  дорабатывает, затем модель выгружается). Бронь `EXTRA_RESERVED_VRAM` возвращается
  ComfyUI;
- кнопка **Free model and node cache** / вытеснение моделей ComfyUI (хук на
  `model_management.unload_all_models` вне выполнения нод) - выгружаются ВСЕ наблюдаемые
  серверы;
- сервер, к которому нодпак **ни разу не обращался** в этой сессии, никогда не
  выгружается - им может пользоваться другой клиент (Jan, curl, второй ComfyUI);
- выгрузить не удалось (сервер занят дольше 30 c, недоступен) - сервер остаётся под
  наблюдением, попытка повторится при следующем запуске воркфлоу.

### Тоггл clear_comfy_vram: выгрузить модели ComfyUI перед генерацией

Обратная задача: не PolyStrata отдаёт VRAM ComfyUI, а ComfyUI освобождает VRAM под
запрос PolyStrata. При включённом тоггле нода Chat **перед генерацией** выгружает модели
САМОГО ComfyUI (`comfy.model_management.unload_all_models()` + `soft_empty_cache` + gc) -
то же, что кнопка **Free model and node cache**: checkpoint/LoRA/ControlNet уходят из VRAM,
и у LLM-запроса больше места. Модель PolyStrata это НЕ задевает (хук авто-выгрузки внутри
выполнения нод серверы не трогает); при нужде ComfyUI загрузит свои модели обратно сам.

- **в одном запуске воркфлоу - ОДИН РАЗ**: лист картинок на входе (несколько `img`-пинов,
  батчи), цикл list-пака, перебор сидов, несколько нод Chat - нода исполняется многократно,
  но после первой очистки выгружать уже нечего (результат тот же), поэтому повторные
  очистки ПРОПУСКАЮТСЯ (в логе - «уже сделана в этом запуске воркфлоу»);
- флаг сбрасывается в начале **каждого** запуска воркфлоу (тот же хук
  `PromptExecutor.execute`, что у авто-выгрузки): очередь из N сидов = до N очисток, но
  если модели между запусками не перезагружались, лишние очистки мгновенны и ничего не
  меняют; а если воркфлоу между запусками снова генерирует картинки (модели загрузились
  заново) - очистка снова реально освободит VRAM;
- выключен (по умолчанию) - нода не трогает память ComfyUI;
- листы на ЛЮБЫХ входах обрабатываются безопасно (list-паки циклов шлют списки куда
  угодно) - и БЕЗ перечисления имён: нормализуется весь набор входов разом, поэтому
  скалярные виджеты (`prompt`, `seed`, `server`, резервы, ... и любые добавленные позже)
  берут ПЕРВЫЙ элемент, список батчей картинок разворачивается в пины - кадры уходят
  ОДНИМ запросом с метками `[Image 1..N]`.

```
Связка «генерация -> описание» в цикле (seed/list-пак):
  [Load checkpoint] ─▶ [KSampler] ─▶ [Chat clear_comfy_vram=ON]
                         ...описание: модели диффузии выгружены - LLM без OOM...
```

```
Цепочка с тяжёлой Comfy-стадией:
  [Chat (reserve_mib=8192)] ──text──▶ [KSampler / видео-ноды]
  ... ComfyUI видит бронь = фактическое потребление PolyStrata ...

Полная отдача перед самой тяжёлой стадией (сквозная цепочка):
  [Chat] ─▶ [Unload] ──any_output──▶ [тяжёлая стадия] ─▶ ... (следующий Chat сам разбудит модель)
```

## Сэмплинг: что реально принимает PolyStrata

Проверено по коду сервера (`serve/server.py`: `check_request_sampling` +
`StrataEngine.sampling_keys`): до движка доходят **только**

`temperature` (0 = жадный), `top_p`, `top_k` (int; движок сжимает до 1..64), `min_p`,
`repetition_penalty` (алиас `repeat_penalty`), `penalty_last_n` (алиас `repeat_last_n`),
`presence_penalty` (≥0), `frequency_penalty` (≥0), `stop` (до 4 строк), `seed` (>0) +
размышления: **`reasoning_effort`** ("none" = thinking off; low/medium/high; "high" сервер
поднимает до xhigh) и **`chat_template_kwargs`** `{"enable_thinking": false}` (конвенция
vLLM/llama.cpp) + `logit_bias` (`{"<token_id>": bias}`, −100..100, −100 = запрет токена).

ВАЖНО про размышления: пресет `none` в ноде Chat шлёт **оба** механизма сразу, потому что
топ-левел поле `enable_thinking` из тела запроса сервер НЕ читает (проверено по
`serve/frontend.py` `openai_to_messages`: `enable_thinking` принимается только внутри
`chat_template_kwargs`, а `reasoning_effort: "none"` маппится сервером в thinking off).

Остальных семплеров llama.cpp у PolyStrata **нет**: `typical_p`, `tfs_z`, `xtc`, `dry`,
`dynatemp`, `mirostat`, `smoothing_factor`/`smoothing_curve`, `top_n_sigma` - движок
strata-poly не ванильный llama.cpp, этих сэмплеров в его сэмплинг-цепочке нет, сервер
молча отбрасывает такие поля (проверено по текущему `main`). Виджетов для них нет
намеренно: контрол, который ни на что не влияет, только путает. Зато:

- **`logit_bias`** (нода Sampling) - запрет/подталкивание токенов: строка на токен,
  `12345` = запрет, `12345:-2.5` = bias; аналог banned_tokens из llama-нод;
- **`extra_sampling`** (нода Sampling) - JSON-объект с любыми полями запроса:
  когда в strata-poly добавят новые семплеры, их можно включить **без обновления нод**
  (`{"xtc_probability": 0.5}`); сегодня неизвестные поля сервер игнорирует.

## Ошибки

| Симптом | Причина и что делать |
| --- | --- |
| `strata-poly: unknown option --vram-elastic`, движок не стартует | В конфиге модели лишний ключ `"vram_elastic": true` - удалите его (см. «Требования»), запустите модель заново. |
| 400 `--vram-elastic` при вызове reserve | То же самое на работающем сервере: конфиг правится, сервер перезапускается. Генерация при этом НЕ роняется - нода пишет «РЕЗЕРВ НЕ ПРИМЕНЁН». |
| 400 `request exceeds the context window: prompt (N tokens) ...` | Промпт с кадрами не влез в окно (например `--max-context 32768`), а двигок запросы не обрезает. См. «Почему кадры съедают контекст»: уменьшите `max_video_frames`/`max_images` (субнода Media, лимиты на каждый пин), `max_frame_side` (там же), ходы Memory. Нода сама подгоняет кадры под окно и объясняет ошибку, если она всё же случилась. |
| 409 `model_busy` | Идёт генерация. У Unload поставьте `wait_s` 30-60; смена модели/резерв повторятся при следующем запуске. |
| 503 при загрузке | Не выполнен `min_free_vram_mib` - свободной VRAM меньше минимума; освободите VRAM (клиент сам повторяет по `Retry-After`). |
| 404 `model not found` | Смена модели через старый сервер без `switch_on_request`, либо поле попало в запрос через `extra_sampling`: обновите PolyStrata / уберите поле. |
| 404 `no model named '...'` при выборе модели | Модели нет на ЭТОМ сервере (дропдаун - объединение по известным серверам) или она исчезла: обновите список (F5/R) и проверьте `strata-*.json`. |
| 422 при переключении | Конфиг выбранной модели неисправен (`strata-<модель>.json`: exe/args/tokenizer) - сервер её не грузит. |
| 503 при переключении | Новая модель не стартовала; сервер вернул прежнюю - смотрите лог сервера. |
| 401/403 | Сервер требует api_key, а ноды его не шлют: откройте доступ с localhost или ослабьте требование ключа на сервере. |
| «Не удалось подключиться» | Сервер не запущен или адрес/порт неверные. |
| В логе «ComfyUI: EXTRA_RESERVED_VRAM не изменён (total VRAM сервера неизвестен)» | Старый сервер без `machine.gpu` в `/v1/status` - обновите PolyStrata. |

## Используемые эндпоинты PolyStrata

- `POST /v1/chat/completions` - OpenAI-совместимый чат (без стриминга; медиа - `image_url` data-URI части);
- `GET /api/models` - установленные модели + текущая (дропдаун ноды; реестр `strata-*.json`);
- `POST /api/models/load` - `{"model": "<id>"}` - переключить сервер на другую модель (см. «Смена модели»); запасной путь - `POST /v1/load` (старые серверы, требует `switch_on_request`);
- `POST /v1/vram` - `{"reserve_mib": N}` / `{"reserve_mib": null}`;
- `POST /v1/unload?wait=N`;
- `GET /v1/status` - модель, состояние, занятая VRAM, `machine.gpu.total_mib` (для брони ComfyUI) и `context.native` (окно движка для префлайта кадров);
- `GET /props` - запасной источник окна (`default_generation_settings.n_ctx`).
